# 8K、C64 全部在生成时的执行路径

在 8K、64 条请求同时生成的同 token 窗口，mHC、MLA/Indexer、稠密投影仍是可定位的差距。R11 紧凑 KDA 投影在当前 LMDeploy 整步节省 0.087 ms（0.53%），八卡全词表和缓存逐位对齐，每 rank 多用 2.125 GiB 权重空间。PR3 采用可处理动态小批量的草稿词表分片，R11 的固定 B8 路径保留为独立研究结果。

64 个真实请求平均分布在八个 H200 上，每 rank 八条。复用历史纯生成窗口的随机 token 生成器及 seed 819289152，每条输入 8,192 个 token，强制生成 256 个，保持 TP1、DP8、EP8。每波只发起这 64 条请求，下一波在全部结束后发出，对应历史滚动负载首波所有请求都已开始且尚未结束的片段。时间窗取输出第 33–224 个 token 中前后两个端点都在 64 条请求同时生成时的区间。每个服务单独跑两次无 profiler 计时，再在第三次相同输入的生成过程中采 16 步 rank 0 trace。原始输出 ID、到达时间和逐步输入保存在[机器可读索引](../../../benchmark/glm53_mega_moe/results/h200_c64_decode.json)列出的 run。

| vLLM MTP0 | 14.668 / 14.644 | 14.656 | 1.000 | 14.301 | 81–100 |
| LMDeploy MTP0 | 16.289 / 16.170 | 16.229 | 1.000 | 15.777 | 84–99 |

LMDeploy 启用 FlashKDA 和 RDMA Mooncake。vLLM 使用历史同机 DeepGEMM MegaMoE 版本 5328ae2fef 及其原服务参数。LMDeploy 的 KV 块长为 64，vLLM 的 SM90 稀疏后端在启动时选定 128。各引擎自行生成的输出可能分岔。核间差值另用同 token 回放比较。

## MTP0 同 token、同位置比较

vLLM 从真实前向保存八个 rank 的请求标识、query token ID 和设备 position。对齐 16 个集体轮，逐项核对 1,024 个 ID/位置与各自的流式输出。八个 rank 的轮号最大绝对偏移为 0，各 rank 启动时间相对 rank 0 的中位偏差最大为 0.769 ms。LMDeploy 逐请求完成真实 8K prefill，再以 decode 方式补齐至相应历史。较早到达截点的行使用分离的临时 KV 和状态槽。计时与 profile 分开。vLLM trace 包含实服采样等步骤，LMDeploy 强制回放执行目标模型、LM head 和 argmax。两个引擎各自计算 KV 和递推状态，目标图内核时间及完整客户端间隔分别给出。

历史 C1 的 mHC、MLA/Indexer、稠密 GEMM 三类合计差 0.912 ms/步，42 次 MegaMoE 合计差 0.024 ms/步。当前同 token C64 下相同三类合计差 +0.973 ms/步，MegaMoE 差 -0.048 ms/步。

所有 CUDA 核区间并集为 15.653 / 14.301 ms/步。包含 42 次 MegaMoE 的目标 CUDA Graph 内部，核区间并集分别为 15.330 / 13.900 ms/步。表格沿用 C1 的 kernel 名称归类，稠密 GEMM 可来自多个模型模块。各核时长之和含可能的并行重叠，集体核也含等待其他 rank 的时间。

mHC 每步有 450 / 181 次核调用。LMDeploy 的有序投影 partial、归并及 RMS 缩放分别占 0.400、0.160、0.185 ms，vLLM 主要落在其 fused TileLang 路径。本文末尾另测有序归并和缩放的融合。

MLA 的具体差异集中在注意力主核。LMDeploy 的 BF16 FlashMLA sparse forward 为 0.630 ms/步，vLLM 的 FlashInfer Hopper paged MLA 为 0.235 ms/步，后者还执行 top-k 转换与重映射。vLLM 将每个 query 当作一行，把 top-k 物理槽当作 page_size=1 的页表，在图外生成执行计划并在设备端按有效长度裁剪。迁移时须校验页步长、KPool 尾部、空行及 CUDA Graph 重放的动态长度。

## MonoKernel R11 的可迁移性

R11 的原测量是每 rank B8、MTP0、真实 64K prefill 后生成 512 步，原生 R10 与 R11 三轮交错均值为 12.37926 → 12.34909 ms/步。KDA BF16 输出投影保持 0 / 2752 / 5504 / 8192 的 split-K 归并，预先压紧 SW128 权重布局和两个 K64 尾块，34 层合计多一份 2.282 GB/rank 权重。128 → 132 CTA 的专家网格在紧凑布局上另省约 4.43 µs/步。无损 FP8 压缩、L2 预取和完整 KDA 单核在该原生整模对照中有各自的回退。

本轮沿用当前 LMDeploy 其余算子，实测两项独立消融。R11 仅替换 34 个 KDA 输出投影，路由、专家网格和状态推进使用当前 LMDeploy。mHC 单独把有序 split-K 投影切回现有 FP32 线性层。每轮都恢复同一份 KV、KDA、KPool 和游标快照，固定所有 rank 的输入，交错运行三种模式各三轮。每个集体步先取八个 rank 的最大 CUDA event 时间，再对步和轮求平均。

| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 LMDeploy | 16.384 / 16.401 / 16.388 | 16.391 | 0 / 158,597,120 | 1024/1024 | 是 |
| R11 紧凑 KDA 输出 | 16.335 / 16.291 / 16.287 | 16.304 | 0 / 158,597,120 | 1024/1024 | 是 |
| mHC 原生 FP32 线性投影 | 16.983 / 16.969 / 16.992 | 16.981 | 0 / 158,597,120 | 1024/1024 | 是 |

对八卡 34 层的真实 KDA 激活单独检查，R11 输出与原投影有 0 / 8,912,896 个 BF16 元素不同，最大绝对差 0。新图每步实见 34 次 R11 核。mHC 对照图中有序 partial 投影确实由 90 次降至 0 次。R11 入口要求展平后为 8 × 8192，C64/MTP3 的目标验证是 32 × 8192，需要另行设计和验证 32 行路径。

另在同一强制轨迹上把 mHC 的 128 个 FP32 partial 有序归并和 RMS 缩放放到同一 Gluon 核。每步实见 90 次融合调用，四轮原生 / 融合均值为 16.386 / 16.385 ms，mHC 核时为 1.331 / 1.336 ms。完整词表有 0 个元素不同，argmax 匹配 1024/1024，缓存及游标逐字节检查结果为一致。

按本次测量，下一处值得单独做接口与数值验证的是 SM90 稀疏 MLA 的页表和执行计划，注意力主核在相同轨迹下相差 0.395 ms/步。mHC 的有序投影已有整步收益，仅减少末端一次发射的实验与控制基本持平。各项上限都要经整步和实际提交量复核。
