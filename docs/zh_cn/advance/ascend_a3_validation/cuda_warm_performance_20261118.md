# PR #5134：H200 充分预热性能复测

更新日期：2026-11-18（Asia/Shanghai）。本页以本轮新测为准；旧的H200百分比已归档，不再作为当前问题清单。

**满足数值前提的迁移对照全部通过本轮预定的持续回退判据。** 34个短工作负载/评分配置中，31个满足数值与资源条件；另有GLM的两项32K保序迁移控制通过。三个大模型的动态HTTP C4均在基线和PR各自重放时出现差异，不能据耗时接近签署严格性能通过。

## 固定版本与方法

普通迁移对照固定442097e8 → f64ab506；2ccf38a4的推理、测试、requirements和src源码树相同。GLM使用两个独立研究工作树f06316de/5e51b671，在各自父版本加入同一个deterministic=True参数；该策略改动不在迁移PR中。源码、checkpoint与环境清单见证据。

- 170个选定模型进程：每格五对全新进程AB/BA，每进程每并发三个实请求预热批次、五个计时批次；单卡/八卡均使用同一批指定设备。
- 主矩阵保存1700个计时批次，含3750次生成响应（960000个输出token）和500次评分；GLM长上下文另有100个计时批次。计时外采集2000次短负载分数响应及长上下文探针，未满足数值前提的样本单列，不混入通过数量。
- 普通生成固定输入prompt、256输出token、greedy/top_k=1、seed42、graph开启、prefix关闭；GLM另测32603输入/32输出、C1、非MTP和MTP3。Decision使用真实评分任务，temperature=1.99241824。
- pipeline设置do_sample=False；HTTP使用原生API的temperature=0/top_k=1。该版本API内部仍构造do_sample=True，但候选只有一个；本轮保留原实现并记录实际配置，没有更改采样分支来制造一致。
- 先完成引擎本身的全部解码图预热，再进行实请求预热。max_batch_size=8时常规图桶为1、2、4、8；HTTP额外覆盖完整C4 prefill，Sage/Agents为668 token，确保MoE hint2已正常调优。
- 计时前后另采完整token/top-k位编码。HTTP捕获仅在计时外启用，进入预热/计时前恢复原始AsyncEngine.generate，并验证控制时间线。
- 每批TTFT/TPOT先取请求均值，每进程再取五批中位数，然后计算五个进程配对的变化及bootstrap区间。所有样本保留，不把批次当作独立进程。
- TPS为批次生成token总数除以提交至全部完成的wall time，包含prefill；TTFT为首个返回token，TPOT按首末输出与实际后续token数计算。长输入/短输出的TPS不能与短输入/长输出跨行比较开销。pipeline不含HTTP/router，HTTP为真实loopback端到端。
- 原判据不变：不利配对中位变化超过5%、至少4/5对超过5%、配对bootstrap95%区间排除0时进入定位。
- 两对Agents HTTP遭遇外部GPU进程重叠，原记录保留，整对按相同顺序用新标签补跑。只按资源证据排除，没有按快慢或数值结果挑选样本。

两侧146项依赖版本一致，CUDA环境无dlinfer/torch_npu/triton-ascend。Torch2.10.0、CUDA Triton3.6.0、FLA/fla-core0.5.2、TileLang0.1.11、NCCL2.27.5等均记录在完整清单中。没有采用A3的CPU18亲和性设置。

Triton缓存核对的是实际产物，不只检查环境变量。复制后的group索引仍可引用原冻结matched/base缓存；本轮所有初始引用产物均按SHA256核对一致，两侧使用同一内容。导出包保留原索引，异地复现时才在新副本重定位路径，不改kernel或调优winner。

## 当前限制与证据

Flash、Intern-S2及本轮新增GLM的动态HTTP C4，在两份源码各自重复请求时均出现token/完整分数差异；充分预热没有使本轮样本满足零容差前提。保序selector不等同整个模型的batch不变性。首个分歧和此前相同历史已保存；不比较已分叉历史后的后续分数，也不把这些计时判成迁移性能通过。

本轮没有修改计算、同步顺序、collective精度、checkpoint或验收阈值。没有把pipeline或固定输入prefill当作独立target主干、MTP HTTP、外网/router、DP4/EP8或长期高并发验收。

完整逐对区间见[性能汇总](evidence/cuda-h200-warm-20261118/performance-summary.json)，逐批计时见[CSV](evidence/cuda-h200-warm-20261118/timing-samples.csv)，显存见[采样记录](evidence/cuda-h200-warm-20261118/memory-samples.json)。显存为200ms NVML采样，不冒称连续精确峰值；未采到的短窗口为null。

GLM的[32K迁移对照](evidence/cuda-h200-warm-20261118/glm-long-performance-summary.json)、[保序开关成本](evidence/cuda-h200-warm-20261118/selector-cost-summary.json)和[16组算子统计](evidence/cuda-h200-warm-20261118/operator-summary.json)分别保存五对数值及区间，不混成单一性能结论。
