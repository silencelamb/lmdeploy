# 99 输入、固定八行的测量先后确认

原补充序列 r0 四个进程按 old/new/new/old 执行，偶数 slot 先 C4，奇数 slot 先 C8。原先相邻的版本配对采用不同的 C4/C8 测量先后，因此这些结果保留为计时先后混杂的记录。Agents 的两组八行版本配对均有 1/64 个测量序列不一致，两个同版本重启也各有 1/64 不一致。相同先后对照 old slot0 / new slot2，以及 old slot3 / new slot1，在 C4 和 C8 分别都是 64/64（资格亦一致）。C8 首个分歧为 rep0 R0/Q0 输出索引 47，出现 74307 或 30576，版本交换时方向反转。该现象和先后条件相关，具体数值原因未由 token 序列证明。

在 r1 开始前固定重新运行两组新进程配对。AB 的旧与新均按先 C4 再 C8 的测量顺序启始，BA 的新与旧均按先 C8 再 C4 的顺序启始。各 rep 如原设计交替。保持相同负载、物理 12/13、64 个零缓存命中输入、输出长度、预热和锁。两个模型都执行，报告逐对吞吐、工作资格和 rank 形状。r0 与 r1 各自报告，不把样本合并签等效。正式 HTTP 及三个独立重点复测组不受此 slot 设计影响。
