# A3 单请求与主机对照数据

[实验与结果](../../a3_host_variability_20261118.md)给出模型、服务参数、CPU 对照和判据。下表的时间单位均为毫秒，吞吐为输出 token/s。A3 旧版 LMDeploy 固定 fb5de87a，dlinfer 固定 3b909634，原生 LMDeploy 固定 2ccf38a4。

| 文件 | 口径 |
|---|---|
| [正式单请求计时](http-c1-timing.csv) | 2,000 条 Sage HTTP C1 完整流式请求。每个版本各 10 个进程，每个进程 100 个固定、等长提示。行顺序即该进程的请求顺序。TTFT 从客户端发起请求到收到首个非空 SSE 内容。其后五列是同一时间窗的连续分解。 |
| [各进程对](process-pairs.csv) | 每个服务独立算 p50/p95/p99。变化百分比为 100 × (新 / 旧 − 1)，延迟为正表示变慢。 |
| [正式计时方式的亲和性复核](affinity-confirmation.csv) | 默认实验完成后，排除 CPU18 并用相同轻量观测额外启动旧、新各 2 个进程，每进程 100 条。每行列同一提示在默认实验前两对和这次独立运行中的延迟。 |
| [H200 和 A3 的同版本离散度](platform-dispersion.csv) | 各进程内取批中位数，再计算这些进程中位数的四分位间距除以其中位数。记录各平台的样本数与 A3 全量结果。 |
| [CPU 对照](host-controls.csv) | C++ 计时为请求 12 ms 休眠的实际返回时间。Ray 计时为调用者开始等待两个确认到等待结束，取决于两个 worker 中较晚返回的一方。H200 两轮内部的 put/direct 分开列。 |
| [真实模型与 Ray 的分层计时](model-timelines.csv) | 另开 8 个已预热进程，每个 60 条。默认亲和性与排除 CPU18 在进程启动前设置。prefill 取两 rank 时间区间的并集，随后依次列出未与 prefill 重叠的前次 ACK 等待，以及未被前两项覆盖的在途投递。这四列加起来等于 TTFT，舍入除外。在途时间可与其他有用工作并行。零值的最长读取/投递分别代表没有达到记录阈值。 |
| [解析器和 worker 的分层计时](frontend-worker-timelines.csv) | 另开旧、新各一个默认亲和性进程，每个 60 条。get_vocab 的 wall/thread 列嵌套在 parser 中。其后 14 列是首 token 时间的互斥分解，按解析器、任一 rank prefill、显式 ACK、在途投递、输出请求、worker 输出与剩余时间依次取尚未覆盖的区间。毫秒数表示这些动作当时在途的时间。 |

[worker 与主机的同窗事件](worker-host-events.csv)列出补充分层记录中超过 100 ms 的设备读取、在模型和确认等待之外的输入投递，以及输出 RPC 开始至 actor 入口、actor 返回至驱动恢复的时间。输出 RPC 等待进入 actor 时，actor 可以正在执行 prefill。外部计数器约每 200 ms 采样一次，表中给出包住该事件的完整采样窗。单个心跳的开始、结束 CPU 只能确定两个采样点。

[固定版本、脚本指纹与计时定义](measurement-definitions.json)还记录了 H200 原始归档的 SHA256、实际用于十次服务的脚本哈希，以及两版单独 CPU 词表实验的结果。

95% 置信区间在 10 对进程中整对有放回重抽 10,000 次，随机种子 20261118。正式主指标取每次抽样中的配对变化中位数。合并 p95 的复核在每次抽样后合并各进程的全部请求再取分位数。两种区间均落入 ±5% 才判定该指标等效。带诊断探针的运行、CPU 控制、旧的混并发样本独立保存。
