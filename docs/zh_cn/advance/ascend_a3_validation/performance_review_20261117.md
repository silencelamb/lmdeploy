## H200

### 较大的百分比来自哪些样本

以下百分比是 **五个配对百分比的中位数**，不是“两侧中位数之比”。TTFT 越低越好，吞吐越高越好。

| 场景/指标 | 基线中位数 → PR 中位数 | 配对变化中位数 | 已记录的配对 bootstrap 95% 区间 | 不利变化超过 5% 的轮数 | 状态 |
| --- | --- | ---: | --- | ---: | --- |
| Agents-A1 HTTP C4，原预热，TTFT | 124.81 → 580.86 ms | +324.32% | [+3.57%, +433.36%] | 4/5 | 触发定位，查到遗漏形状的 MoE 在线调优 |
| 同组吞吐 | 532.78 → 435.36 token/s | −17.63% | [−18.41%, +0.16%] | 3/5 | 原始下降保留，与同组调优开销一起解释 |
| Agents-A1 HTTP C4，完整形状预热，TTFT | 110.54 → 109.71 ms | +7.76% | [−42.68%, +43.23%] | 3/5 | 未触发持续回退；区间过宽，不能证明 ±5% 等效 |
| Intern-S2 Preview HTTP C1，TTFT | 186.77 → 200.71 ms | +6.33% | [−7.68%, +26.24%] | 3/5 | 未触发持续回退；同样不能证明 ±5% 等效 |

数据与完整逐轮值：[生成性能摘要](evidence/cuda-h200-20261116/performance-summary.json)。本次从保存的 base/pr 数组重新计算配对百分比、中位数和触发条件，结果与原摘要一致；95% 区间按原记录引用，没有换一种统计方法重新包装结论。

原判据是：不利配对中位变化超过 5%、至少 4/5 轮超过 5%、配对 bootstrap 95% 区间排除 0，才进入持续回退定位。它是定位触发条件，**“未触发”不等于已经证明性能等效**。

Agents 原 HTTP 预热可能形成 3+1 等分批，没有覆盖 668-row 的 MoE `tune_hint=2`。两侧独立诊断均复现两次在线调优合计约 491 ms，模块/磁盘加载仅约 4–8 ms。补充 profile 先用正常 raw completion 覆盖精确形状，让原算法自行调优，再做五对相同的 C1/C4 测量；没有指定调优 winner 或修改计算/同步。完整预热后，Agents C4 吞吐配对中位 +0.89%、TPOT −1.50%，但 TTFT 的上述波动仍原样保留。原始慢样本没有删除或改标为通过。[诊断及预热配置](cuda_regression_20261116.md#性能方法与结果)

两种中位数统计可能方向不同。例如完整预热 Agents C4 TTFT：两侧中位数之比为 −0.75%，但逐对变化为 +14.09%、−42.68%、+43.23%、−19.56%、+7.76%，其配对中位为 +7.76%。这不是算术错误，也不能挑其中更有利的一个数字宣称加速。

### 已测范围与未验收范围

- Sage-A1.5、Agents-A1、GLM-5.3-Flash、Intern-S2 的合格 pipeline/C1/C4，以及合格 HTTP 场景，在记录的完整预热对照中未触发持续回退。MTP3 性能只覆盖 pipeline。
- Intern-Decision-4B 是评分任务：使用 RPS、prefill-token TPS 和评分延迟；没有生成 TPS/TTFT/TPOT。[评分性能数据](evidence/cuda-h200-20261116/decision-performance-summary.json)
- GLM-5.3-Flash / Intern-S2 **HTTP C4** 因输出不自重复未获本轮性能验收资格，不能算“性能对齐”。
- GLM-5.3 原长上下文受 selector 非重复性阻塞；后续 `deterministic=True` 的 32 次整模型控制只验证正确性，未测保序开销。加载、编译和整轮验证 elapsed 不能当作推理性能。[整模型控制范围](glm53_stable_selector_fullmodel_20261117.md)
- H200 gated-norm 算子独立测量的配对中位变化约 −1.46% 至 +0.22%。target 主干没有独立性能测量；真实外网/router、用户 DP4/EP8 生产链路、高并发长稳、MTP HTTP 性能仍未验证。

完整配置、逐轮数据及显存采样边界见 [H200 主报告](cuda_regression_20261116.md#性能方法与结果)。

### 旧 dlinfer → native 的历史 HTTP 信号仍未关闭

以下是首组 baseline→native（5 轮）与反向 native→baseline（7 轮）的原始统计，均为新相对旧的变化。两组独立比较，不能把两组的绝对吞吐直接拼成一个新旧对照。

| 模型/指标 | 首组变化 | 反向复测变化 | 当前结论 |
| --- | ---: | ---: | --- |
| Sage-A1.5 C1 总吞吐 | −15.57% | +13.82% | 初组下降未重复，不能只挑任一组下结论 |
| Sage-A1.5 C4 总吞吐 | −6.39% | +1.09% | 未重复确认超过 5% 的总吞吐下降 |
| Sage-A1.5 C4 流式输出速度 p50 | −12.18% | −5.87% | 重复下降信号，尚未完成归因；当时为 MTP3，另有正确性/接受长度干扰 |
| Agents-A1 C4 总吞吐 | −13.68% | −2.67% | 未重复确认超过 5% 的总吞吐下降 |
| Agents-A1 C4 流式输出速度 p50 | −7.13% | −8.99% | 重复下降信号，尚未完成归因 |
| Agents-A1 C1 TTFT p95 | +5.96% | +5.07% | 原小样本尾延迟信号保留，约 +39 / +35 ms |

流式输出速度是 `(输出token数−1)/(末次−首次非空SSE时间)`，包含输出传递和调度，MTP 还受多 token 突发影响；不是纯算子速度。Agents 固定 C4 pipeline 控制未复现相同下降，但它不能覆盖 HTTP 信号。以上数据并未在当前 HEAD、当前依赖和主机缓解条件下完成同样的新旧 HTTP 复测，因此既不能宣布已修复，也不能将历史信号直接认定为当前 HEAD 的因果回归。

### norm 重构、GDN 修复与主机延迟分别说明

norm 重构初测确有 Sage C1 TTFT +13.88%、Agents C4 TTFT +23.19%，以及 Agents 长生成 C1 TTFT +14.15% / C4 吞吐 −5.15%。这些数字仍保存在[原始性能观察](gated_norm_refactor_20261115.md#性能观察)，并没有被删除。

后续在同一对 worker 内交替旧/新 norm，各场景 8 对 AB/BA：Agents C1 TTFT 配对中位 −4.17%（区间 [−9.49%, +4.93%]），C4 吞吐 +4.68%（区间 [−1.09%, +15.59%]），原下降未稳定复现；实际该形状的 norm NPU 二进制相同。该实验两侧都已原生迁移，不能用来关闭上一节的 dlinfer→native HTTP 信号，也没有证明所有包装/调度开销都为零。[完整 norm 性能调查](gated_norm_performance_20261116.md)

GDN 的百分比还需看比较方向：新版编译器的 B16/Q4 表中 **+4.83% 是 stage3 多缓冲相对 stage1 单缓冲更慢**，不是说 PR 的单缓冲保护增加了 4.83%。另一组 target 主干的 +2.58% 只出现在一个顺序/rank 视角，反向同 rank 为 −2.18%；两 rank 是同一请求的两个视角。它们是微内核/冻结 target 的控制，不能外推为完整 MTP HTTP 性能。[编译器与 GDN 性能表](mtp_ray_investigation_20261116.md#新版正确多缓冲与单缓冲的性能)

主机约半秒停顿已有独立的 Ray/RPC、CPU18 调度/softirq 与纯 C++ 控制。排除 CPU18 的临时绑核在有限窗口内有效，但不是旧/新迁移 HTTP 性能复测，也未证明此前每一次慢样本都由同一根因触发；具体回调和永久修复仍开放。[独立主机延迟报告](ray_host_latency_20261117.md)

## 复核方法与证据

本次从已有 JSON 重算了 H200 的 98 个指标组（生成与 Decision 合计）、A3 历史 HTTP 的 11 个场景及 norm 的 6 个配对指标。H200 只有原 Agents C4 TTFT 触发已约定的持续回退定位；完整预热后的两项 TTFT 中位增幅超过 5% 但不满足持续性/区间条件，原值和不确定性均保留。

[复核结果和输入文件 SHA256](evidence/performance-review-20261117/audit.json)保存每个较大增幅的逐对值、原区间、两侧中位数和统计口径；[可复制的 CPU 复核脚本](evidence/performance-review-20261117/review_performance.py.md)可从这些固定样本重新生成结果。原始数字及样本保持不变；本次只是校准结论范围，不追加模型运行，不重新排查已经按用户要求仅作记录的跨 prefix-cache 数值现象。
