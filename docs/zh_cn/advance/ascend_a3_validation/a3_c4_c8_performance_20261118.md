# A3 四路、八路吞吐与独立复测

本轮 1、4、8 并发的 HTTP 整批吞吐与迁移前整体接近。两个模型的六个配对中位变化落在 −2.47% 至 +1.97%，单次进程配对的波动更大。Sage 单请求的 p95 首 token 延迟在 8 对中有 7 对上升，建议镜像 QA 复核。[完整指标](evidence/a3-c4-c8-20261118/results/comparison.csv) · [独立复测与初测对照](evidence/a3-c4-c8-20261118/results/repeat-comparison.csv)

同一部署配置下对比旧 LMDeploy fb5de87a + dlinfer 3b909634 与原生 LMDeploy 2ccf38a4。原生 driver/worker 启用导入 guard。Agents 无 MTP，Sage 使用 MTP3。AB 与 BA 各 4 对，统计单位为一次全新的旧、新进程配对。HTTP C4 和 C8 每个进程各测 64 条请求，各自保持零 prefix 命中。

正式 HTTP C8 吞吐的配对中位变化为 Agents-A1 -1.23%（不确定），Sage-A1.5 MTP3 +0.22%（等效）。C4 与 C8 各自反映给定在途数的服务处理量，部署判断还要看首 token 延迟、后续 token 耗时和同时满足目标的请求数。

在这个 171 输入、128 输出的负载上，新版从 C4 提到 C8 后，Agents 与 Sage 的总吞吐上升，两模型 C8 的 512 个请求均未同时达到 TTFT ≤3 秒及流速 ≥40 tok/s。旧版也分别仅有 0/512 和 1/512 个达标。独立 norm64 复测没有重复此前 C4 吞吐下降 5.35% 的方向。Sage HTTP C1 的首 token 尾延迟是本轮应带给 QA 的不利信号。

## 怎样读百分数和区间

以第一次 Agents 离线 C4 为例，8 对吞吐变化依次为 −0.73%、−8.62%、+9.23%、+10.33%、+6.25%、+15.42%、+3.13%、−1.93%。五对变快，三对变慢。排序后的两个中间值为 +3.13% 与 +6.25%，平均得到 +4.69%。方括号中的 +10.33% 是这次吞吐估计的上界。首 token 延迟的点估计为 −10.31%，每个后续 token 耗时的点估计为 −2.55%，两项的负数都表示更快。

95% 置信区间反映典型版本差异估得有多准。从 8 对新旧进程中每次重抽 8 对，同一对可以被重复抽中。每次算一个中位数，重复 10,000 次，取这些中位数中间的 95%。[-1.93%, +10.33%] 意味着按当前实验精度，典型吞吐变化可能略降，也可能上升。TTFT p95 则回答 95% 的单个请求在多长时间内能收到首 token。统计等效使用事先约定的 ±5% 带，完整区间都在带内才判等效。[原始点与区间示意](evidence/a3-c4-c8-20261118/results/previous-c4-reading.png) · [本次吞吐逐对图](evidence/a3-c4-c8-20261118/results/c4-c8-throughput.png)
